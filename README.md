# RAG Chunking Strategy Evaluation System

A Retrieval-Augmented Generation (RAG) evaluation system for comparing
how different document chunking strategies affect question-answering
performance.

The project compares three chunking strategies:

-   Fixed-size Chunking
-   Recursive Chunking
-   Semantic Chunking

Each strategy uses its own ChromaDB collection. The same embedding
model, retrieval configuration, reranker, language model, and evaluation
metrics are used across all three strategies so that the chunking
strategy is the primary experimental variable.

The system supports both single-question evaluation and full-dataset
evaluation through Python scripts and a Streamlit interface.

## Project Objective

The objective is to evaluate the effect of document chunking strategies
on the quality of answers generated by a RAG system.

## Features

-   PDF, TXT, and DOCX document support
-   Fixed-size, recursive, and semantic chunking
-   Separate ChromaDB collection of respective chunking strategy
-   Single-question and full-dataset evaluation
-   Cosine Similarity and ROUGE-L metrics
-   Strategy-level aggregation
-   Streamlit web interface

## Evaluation Metrics

### Cosine Similarity

Measures semantic similarity between the generated answer and reference
answer using embeddings.

### ROUGE-L

Measures overlap between generated and reference answers using the
longest common subsequence. The project uses the ROUGE-L F1 score.

Reference answers are used only for evaluation and are never embedded
into the vector database. This prevents evaluation data leakage.

## Final Experimental Results

The final experiment used a Q&A dataset containing more than 200+
question-answer pairs.

| Chunking Strategy | Avg. Cosine Similarity | Avg. ROUGE-L |
|---|---:|---:|
| Fixed | 0.76 | 0.43 |
| Recursive | 0.82 | 0.49 |
| Semantic | 0.87 | 0.56 |

For this dataset and experimental configuration, semantic chunking
produced the highest average scores on both metrics. These results are
specific to the evaluated dataset and pipeline and should not be
interpreted as a universal result for all RAG workloads.

## Q&A JSON Format

The Q&A file must contain a JSON list:

``` json
[
    {
        "question": "What is the main objective of the document?",
        "answer": "The main objective is to explain the proposed system and its methodology."
    },
    {
        "question": "What methodology is discussed?",
        "answer": "The document discusses a methodology for processing and evaluating the proposed system."
    }
]
```

## Installation

### 1. Clone the repository

``` powershell
git clone <YOUR_GITHUB_REPOSITORY_URL>
cd rag-chunking-evaluation
```

### 2. Create a virtual environment

``` powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
```

### 3. Install dependencies

``` powershell
pip install -r requirements.txt
```

## GPU Setup 

A GPU is recommended for faster local LLM generation.

Verify PyTorch:

``` powershell
python -c "import torch; print(torch.__version__); print('CUDA available:', torch.cuda.is_available())"
```

A CUDA-enabled installation should report:

``` text
CUDA available: True
```

CPU execution is also possible, but local LLM generation may be slower.


## Run the Streamlit Application

``` powershell
streamlit run app.py
```

Open the URL shown by Streamlit, usually:

``` text
http://localhost:8501
```

## Conclusion

This project provides an experimental RAG framework for studying how
document chunking strategies affect generated-answer quality.

The system isolates chunking as the primary experimental variable while
keeping the embedding model, retrieval configuration, reranker, language
model, and evaluation metrics consistent.

For the evaluated dataset and configuration, semantic chunking achieved
the highest average scores on both metrics.

The complete system can be reproduced locally by cloning the repository,
installing dependencies, providing a document and corresponding Q&A
dataset, and launching the Streamlit application.
